## Epic 1：基础、启动与运行时基线

### 目标
建立项目的可启动、可进入、可导出、可验证的基础壳层。

### 范围
**包含：**
- 仅 Windows / Steam 单机基线
- Godot 4.5.1 + C# 项目结构
- 主菜单与主场景入口
- 基础启动流与运行时 bootstrap
- 导出验证和启动稳定性验证

**不包含：**
- 完整夜晚敌军系统
- 完整经济与成长
- 完整 meta 与审计面

### 依赖
- None

### 交付结果
玩家可以从主菜单稳定进入项目，项目可在目标平台边界内启动和运行。

### 用户故事
- 作为玩家，我可以启动游戏并到达主菜单，从而让产品像一个真正可运行的版本。
- 作为玩家，我可以从稳定入口开始新的 run，从而让核心游戏稳定开始。
- 作为开发者，我可以验证 Windows 启动 / 导出行为，从而让后续功能建立在可靠基线上。
- 作为玩家，我可以访问关键顶层导航，从而让启动流程可理解。

---

## Epic 2：核心生存循环与 HUD 可读性

### 目标
建立最小可玩的 Day/Night 生存循环，并让玩家能读懂当前状态。

### 范围
**包含：**
- Day/Night 状态机
- 城堡 HP
- 胜利/失败条件
- 基础 HUD
- 运行时提示与结果表达的最小闭环
- 最小 onboarding 节律

**不包含：**
- 高复杂度战斗压力表达
- 完整经济与成长深度
- 完整结果/战报 polish

### 依赖
- Epic 1

### 交付结果
玩家能进入一局，经历昼夜循环，看到基础状态，并在失败或推进时理解当前发生了什么。

### 用户故事
- 作为玩家，我可以看到当前是白天还是夜晚，从而知道自己处于 run 的哪个阶段。
- 作为玩家，我可以看到城堡生命值，从而理解生存风险。
- 作为玩家，我只会在城堡被摧毁时失败，从而让失败规则保持清晰。
- 作为玩家，我可以在撑过一夜后进入下一天，从而让 run 获得有意义的推进。
- 作为玩家，我可以获得基础提示与结果反馈，从而让循环是可读的。

---

## Epic 3：战斗压力与防线验证

### 目标
让夜晚真正成为对白天准备的系统性考试。

### 范围
**包含：**
- 波次预算与通道
- 按节奏刷怪
- 目标优先级与路径失败回退
- 友伤禁用战斗逻辑
- 夜晚压力表达
- 相机/交互压力相关反馈基础

**不包含：**
- 完整 progression 深度
- 完整 meta 层
- 完整 config audit surfaces

### 依赖
- Epic 1
- Epic 2

### 交付结果
夜晚防守成为真实挑战；玩家能感受到压力升级、路径后果和防线是否有效。

### 用户故事
- 作为玩家，我可以面对逐步升级的夜间波次，从而让游戏检验我的准备。
- 作为玩家，我可以依赖确定性的敌人寻路和索敌行为，从而让失败显得公平。
- 作为玩家，我可以观察敌人被阻挡时的反应，从而让空间决策具有意义。
- 作为玩家，我可以足够清晰地读懂战斗压力，从而理解自己的防线究竟在哪些地方失守。
- 作为玩家，我的存活或崩盘应当取决于真实的防线配置，而不是任意混乱。

---

## Epic 4：经济、建造与成长系统

### 目标
把白天准备期真正做成有代价、有方向、有成长的策略层。

### 范围
**包含：**
- 资源系统
- 债务与税收规则
- 建造与 footprint
- 升级与修理
- 训练队列
- 科技系统
- 奖励选择与 run 内成长

**不包含：**
- 平台服务层
- 完整 settings/save polish
- 最终审计与迁移闭环

### 依赖
- Epic 2
- Epic 3

### 交付结果
玩家在白天做出的经济与建设选择，会以清晰而严苛的方式影响夜晚结果。

### 用户故事
- 作为玩家，我可以把金币和铁投入到有意义的防守决策中，从而让白天阶段真正重要。
- 作为玩家，我可以进入债务状态并感受到其限制，从而让资源失误真正有分量。
- 作为玩家，我可以摆放带有占地后果的建筑，从而让地图空间具备策略意义。
- 作为玩家，我可以训练单位并管理队列，从而让军事规划成为生存的一部分。
- 作为玩家，我可以升级、维修并投资科技，从而让长程 run 结构真正重要。
- 作为玩家，我可以选择每晚奖励，从而让每一局 run 以不同方向发展。

---

## Epic 5：元系统、存档与平台服务

### 目标
把核心玩法提升为产品级体验，支持连续游玩、设置调整和平台完整性。

### 范围
**包含：**
- 自动存档
- 云存档与冲突策略
- 设置、音频、输入、本地化
- 成就
- 性能模式与性能门
- Steam 相关平台要求

**不包含：**
- 最终 UI 收口
- 配置审计可视面全量完成
- 最终 production closure

### 依赖
- Epic 1
- Epic 2

### 交付结果
玩家可以稳定保存、继续、调整设置，并在平台边界内获得一致产品体验。

### 用户故事
- 作为玩家，我的 run 会被安全自动存档，从而保护长时段会话。
- 作为玩家，我可以修改设置并让其持续生效，从而让游戏适配我的机器和偏好。
- 作为玩家，我可以在支持语言之间切换，从而让 UI 在 zh-CN 和 en-US 下保持可用。
- 作为玩家，我可以获得符合账号归属规则的云存档行为。
- 作为玩家，我可以依赖游戏的性能预设，从而让更长的 run 保持稳定。

---

## Epic 6：UI 接线、可审计性与生产收口

### 目标
把现有成熟系统与治理能力收束成真实可读、可交付、可复盘的完整 M1 体验。

### 范围
**包含：**
- 六大 UI slice 的真实 surface 收口
- MainMenu / HUD / Combat / Economy / Meta / Config Audit 统一接线
- 战报读面
- 迁移状态和配置审计状态表达
- 玩家面与治理面的最终桥接

**不包含：**
- 全新玩法大扩展
- 新平台移植
- 重做既有 PRD 基线

### 依赖
- Epic 2
- Epic 3
- Epic 4
- Epic 5

### 交付结果
M1 从“系统大多存在但玩家面不完整”提升为“玩家能读懂、能验证、能复盘的可交付垂直切片”。

### 用户故事
- 作为玩家，我可以通过清晰入口界面理解启动与继续状态。
- 作为玩家，我可以通过稳定的运行时界面读懂结果、提示和错误。
- 作为玩家，我可以通过专用面板管理经济和成长，而不是靠猜测行为。
- 作为玩家，我可以通过清晰 UI 读懂 Meta 状态、存档状态和总结状态。
- 作为开发者或高级玩家，我可以通过受治理、可读的界面检查配置、迁移和战报元数据。
- 作为团队，我们可以把 M1 构建视为真实垂直切片，而不是一堆部分化系统的集合。
